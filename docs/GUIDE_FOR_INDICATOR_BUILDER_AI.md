# راهنمای رسمیِ «AIِ اندیکاتورساز» — چگونه یک اندیکاتورِ جدید بساز، تست و به بانک اضافه کن

> **مخاطب:** یک عاملِ هوش‌مصنوعی (یا انسان) که وظیفه‌اش **افزودنِ اندیکاتورِ تازه به بانکِ ۴۰۱‌تاییِ پروژه** است.
> **جایگاهِ تو در زنجیره:** تو «ماده‌ی خام» می‌سازی. اندیکاتورِ تو به‌تنهایی معامله نمی‌کند؛
> بلکه بعداً «AIِ استراتژی‌ساز/احیاکن» آن را به‌عنوانِ **سیگنال یا فیلترِ رژیم** در یک لایه صدا می‌زند.
> پس هدفِ تو ساختِ یک ابزارِ **تمیز، بدونِ look-ahead، معنادار و کاشف‌شدنی** است — نه یک استراتژیِ کامل.
>
> این سند را **کامل** بخوان. در انتها یک چک‌لیستِ پذیرش هست که تا همه‌ی بندهایش سبز نشود، اندیکاتورت وارد بانک نمی‌شود.

---

## ۰. فلسفه‌ی حاکم (چرا اصلاً اندیکاتورِ تازه؟)

پروژه یک تیمِ تحقیقاتیِ الگویابی در دادگانِ XAUUSD/EURUSD است. یکی از **هشت اشتباهِ رایج** پروژه این است:

> **اشتباه #۳:** «تمرکز روی چند اندیکاتورِ ساده مثلِ MA و غفلت از اندیکاتورهای فوق‌العاده و پیچیده‌ی دیگر
> (مثلِ Alligator, Ehlers cycle, Hurst, ...) و بعد اعلامِ سریعِ سوخته‌بودنِ لایه.»

نقشِ تو مستقیماً **رفعِ همین اشتباه** است: هرچه بانک غنی‌تر و مفهومی‌تر باشد، AIِ استراتژی‌ساز ابزارِ بیشتری
برای زنده‌کردنِ لایه‌های سوخته دارد. پس **دنبالِ مفاهیمِ عمیق باش**، نه یک MA دیگر:

- آماری/فراکتالی (Hurst, R², entropy, fractal dimension, DFA, sample-entropy)
- چرخه/DSP (فیلترهای Ehlers، تبدیلِ هیلبرت، MESA، wavelet-energy)
- ریزساختار (order-flow proxy، حجمِ تیک، عدمِ‌تعادلِ بدنه‌ی کندل)
- رژیم‌محور (تشخیصِ روند/رنج، شکستِ ساختار، volatility-regime)
- بین‌بازاری (رابطه‌ی DXY↔EURUSD، طلا↔بهره‌ی واقعی — دادگانِ DXY در `data/` هست)

## ۱. معماریِ بانک (این‌ها را باید دقیقاً رعایت کنی)

### ۱.۱ محلِ فیزیکی
```
web_tool/src/indicators/
├── contracts.ts        ← قراردادِ ثابت (IndicatorDef, IndicatorValue, IndicatorSnapshot@v1). دست نزن مگر با نسخه‌ی v2.
├── bank.ts             ← فقط concat می‌کند: تمام فایل‌های دسته را جمع و export می‌کند.
├── registry.ts         ← buildSnapshot() + کشِ تنبل. اندیکاتورِ تو اینجا خودکار ثبت می‌شود.
└── bank/
    ├── kit.ts          ← helperهای ریاضیِ بدونِ look-ahead + factoryِ makeKit(). از این‌ها استفاده کن.
    ├── trend.ts        ← دسته‌ی روند/میانگین
    ├── momentum.ts     ← دسته‌ی مومنتوم/اسیلاتور
    ├── volatility.ts   ← دسته‌ی نوسان + حجم
    ├── statistical.ts  ← دسته‌ی آماری/فراکتالی
    ├── cycle.ts        ← دسته‌ی چرخه/DSP اِهلرز
    ├── structure.ts    ← ساختاری/روند-دنبال‌کن (supertrend, psar, ...)
    ├── composite.ts    ← ترکیبی + تبدیلِ قیمت (overlap)
    ├── pattern.ts      ← الگوهای کندلی (±۱۰۰/۰)
    └── variants.ts     ← بسطِ پارامتریِ غیررند (خانواده‌های _fib / _lucas)
```

### ۱.۲ قراردادِ یک اندیکاتور (`IndicatorDef`)
هر اندیکاتور یک شیء با این شکل است (از `contracts.ts`):

```ts
interface IndicatorDef<P> {
  name: string                 // نامِ یکتا و کوتاه، snake_case  (مثل 'hurst', 'reflex', 'kama')
  defaults: P                  // پارامترهای پیش‌فرض           (مثل { period: 64 })
  paramKeys: (keyof P)[]       // ترتیبِ ثابتِ کلیدها برای کلیدِ کش
  desc?: string                // توضیحِ کوتاهِ فارسی (در کاوشگر و مستندات دیده می‌شود)
  active?: boolean             // ⚠️ همیشه false برای اندیکاتورِ تازه (پایین توضیح)
  category?: string            // trend|momentum|volatility|volume|statistical|cycle|composite|overlap|pattern
  source?: string              // EN | RU | CN | deep-web  (منبعِ کشف، برای ردیابیِ علمی)
  compute: (candles: Candle[], params: P) => IndicatorValue   // ← قلبِ کار
}
```

`IndicatorValue` می‌تواند این‌ها باشد:
- `number[]` — یک سری (رایج‌ترین: مثلِ EMA, RSI). آخرین مقدارش با `snap.last(name)` گرفته می‌شود.
- `number` — یک اسکالر.
- `Record<string, number[]>` — چند-سری (مثلِ `{ macd, signal, hist }` یا `{ jaw, teeth, lips }`).
  آخرین مقدارِ زیرسری را با `snap.series(name)` بگیر و دستی index کن.

### ۱.۳ قانونِ طلایی: `active: false` (کشِ تنبل)
همه‌ی اندیکاتورهای بانک `active:false` ثبت می‌شوند. **این یعنی هزینه‌ی محاسباتی صفر تا زمانِ استفاده.**
رجیستری تنبل است: تا وقتی یک لایه‌ی استراتژی صریحاً `snap.series('نامت')` یا `snap.last('نامت')` را صدا نزند،
`compute` تو **اصلاً اجرا نمی‌شود**. بنابراین:
- افزودنِ ۱۰۰ اندیکاتورِ تازه، مسیرِ زنده‌ی سایت (`/api/decision`) را کند نمی‌کند.
- **برابریِ بیت‌به‌بیتِ** snapshotِ طلایی حفظ می‌شود (چون هیچ لایه‌ای هنوز آن‌ها را نمی‌خواند).

اگر نامت با یک اندیکاتورِ هسته‌ی موجود (مثلِ `ema`, `rsi`, `adx`, `vortex`) برخورد داشته باشد، نسخه‌ی هسته
اولویت دارد و نسخه‌ی تو نادیده گرفته می‌شود. پس **نامِ یکتا انتخاب کن.**

### ۱.۴ قانونِ مطلقِ «بدون look-ahead»
هر مقدارِ `out[i]` باید **فقط** از `candles[0..i]` ساخته شود. هرگز از `candles[i+1]` یا آینده استفاده نکن.
- سری‌ات را با `NaN` (یا مقدارِ خنثای منطقی) پر کن تا وقتی داده‌ی کافی نداری.
- helperهای `kit.ts` (`smaArr, emaArr, rmaArr, wmaArr, stdArr, trArr, highest, lowest`) همگی از پیش
  forward-safe هستند — از آن‌ها استفاده کن تا خطا نکنی.

### ۱.۵ قانونِ اعدادِ غیررند (اشتباه #۷)
اگر اندیکاتورت یک خانواده‌ی تک‌پارامتری است (فقط `period` دارد)، به‌جای اعدادِ رند (50/100/200)
از دوره‌های **فیبوناچی** `[3,5,8,13,21,34,55,89,144,233]` یا **لوکاس** `[4,7,11,18,29,47,76,123,199]`
استفاده کن و آن را در `variants.ts` با `expandPeriodFamily(...)` بسط بده. این دقیقاً برای اجتناب از
over-fitِ اعدادِ رند است.

## ۲. گام‌به‌گام: چطور اندیکاتور بساز (روالِ عملی)

### گام ۱ — تفکرِ خطی + غیرخطی روی مفهوم
قبل از یک خطِ کد، دو سؤال را کتبی جواب بده:
1. **این اندیکاتور از لحاظِ مفهومی/ریاضی/آماری دقیقاً چه چیزی را اندازه می‌گیرد؟ فلسفه‌ی اصلی‌اش چیست؟**
2. **چه مشکلی از AIِ استراتژی‌ساز حل می‌کند؟** (مثلاً «تشخیصِ رنج قبل از ورود» یا «کیفیتِ خطیِ روند».)
اگر جوابِ سؤال ۲ «هیچ چیزِ تازه‌ای که ۴۰۱ اندیکاتورِ موجود ندهند» بود، **نساز** — تکراری است.

### گام ۲ — پیاده‌سازی در فایلِ دسته‌ی درست
مثالِ کامل (افزودنِ یک اندیکاتورِ آماریِ فرضی `dfa` به `statistical.ts`):

```ts
// در بالای فایل، K و def از قبل هست:  const K = makeKit(); const { def } = K
// DFA — Detrended Fluctuation Analysis: نمای مقیاس‌بندیِ حافظه‌ی بلندمدتِ سری
def('dfa', 'statistical', 'deep-web', { period: 100 }, ['period'],
    'تحلیلِ نوسانِ بدونِ‌روند (نمای مقیاس‌بندیِ حافظه)', (c, p) => {
  const x = closes(c), n = x.length, out = NaNArr(n)
  for (let i = p.period - 1; i < n; i++) {
    // ... محاسبه‌ی فقط روی x[i-period+1 .. i]  (بدونِ look-ahead)
    out[i] = /* ... */ 0
  }
  return asSeries(out)
})
```
اگر خانواده‌ی تک‌پارامتری است، در `variants.ts`:
```ts
expandPeriodFamily('dfa_fib', 'statistical', 'composite', 'DFA', (per) => (c) => asSeries(/*...*/), FIB_PERIODS)
```

### گام ۳ — تستِ صحت (اجباری، سه لایه)
هر سه تست باید پاس شوند:

**۳.۱ تستِ بدونِ look-ahead (مهم‌ترین):**
اگر ذره‌ای کندلِ آینده را وارد کنی، همه‌ی نتایجِ پروژه بی‌اعتبار می‌شود. تستِ قطعی:
```bash
# اندیکاتور را روی close[0..k] و بعد روی close[0..k+50] حساب کن.
# مقدارِ اندیکاتور در اندیسِ k باید در هر دو حالت *دقیقاً یکسان* باشد.
```
یک اسنیپتِ Node برای این کار در `tools/` بگذار (مثلِ الگوی `tools/verify_parity.mjs`).

**۳.۲ تستِ برابریِ بیت‌به‌بیت (اجباری):**
افزودنِ اندیکاتورِ تو **نباید** خروجیِ `/api/decision` را تغییر دهد (چون `active:false` است و هیچ لایه‌ای
هنوز صدایش نمی‌زند). اجرا کن:
```bash
cd web_tool && node tools/decision_parity.mjs      # باید PASS (بیت‌به‌بیت) بدهد
```
اگر این تست بشکند یعنی یک اثرِ جانبی ناخواسته گذاشته‌ای (مثلاً نامت با هسته برخورد کرده) — برطرف کن.

**۳.۳ تستِ سلامتِ خروجی:**
- سری هم‌طولِ کندل‌هاست، ابتدا NaN و بعد مقادیرِ متناهی.
- روی هر ۶ تایم‌فریمِ XAUUSD (M5/M15/M30/H1/H4/D1) بدونِ crash اجرا می‌شود و NaNِ همه‌جا نمی‌دهد.

### گام ۴ — ثبت در نقشه‌ی دسته‌ها
`bank.ts` فایلت را خودکار می‌گیرد (اگر آرایه‌ی items را export کنی و در `bank.ts` concat شود).
مطمئن شو `_aggregate.ts` / `bank.ts` فایلت را می‌بیند و `registrySize()` به‌اندازه‌ی تعدادِ افزوده‌شده بالا رفت.

### گام ۵ — مستندسازی (اجباری، جای مشخص)
برای **هر** اندیکاتورِ تازه، در فایلِ دسته‌اش زیرِ `docs/indicators/` (مثلِ `docs/indicators/statistical.md`)
این چهار بخش را بنویس (این فرمتِ رسمیِ پروژه است):
- **مفهوم/ریاضی/آماری:** دقیقاً چه چیزی را نشان می‌دهد؛ فلسفه‌ی اصلی.
- **کاربرد:** کجاها به‌کار می‌آید و چه مشکلاتی را حل می‌کند.
- **تگ/هشتگ:** چند عبارتِ کلیدی برای جست‌وجو (مثلِ `#mean-reversion #regime-filter`).
- **استفاده‌ی خلاقانه:** یک ایده‌ی غیربدیهی برای AIِ استراتژی‌ساز.

## ۳. چطور AIِ استراتژی‌ساز اندیکاتورِ تو را مصرف می‌کند (تا بدانی خروجی‌ات باید چه شکلی باشد)

درونِ یک لایه، مصرف چنین است:
```ts
import { buildSnapshot } from './indicators/registry'
const snap = buildSnapshot('XAUUSD', 'M15', candles)
const h = snap.last('hurst', { period: 64 })      // آخرین مقدارِ سری
const r2series = snap.series('r2', { period: 20 }) // کلِ سری برای شرطِ چند-کندلی
```
پس خروجیِ تو باید:
- **مقیاس‌پذیر و تفسیرپذیر** باشد (مثلاً hurst همیشه حولِ 0..1 با آستانه‌ی 0.5؛ chop با آستانه‌های 38.2/61.8).
- **آستانه‌ی طبیعی** داشته باشد که در `desc` یا مستندات ذکر کنی، تا AIِ استراتژی‌ساز بداند کجا فیلتر بگذارد.

## ۵. کاری که هرگز نباید بکنی
- ❌ استفاده از کندلِ آینده (look-ahead) — کلِ پروژه را بی‌اعتبار می‌کند.
- ❌ `active:true` گذاشتن — مسیرِ زنده را کند و برابریِ بیت‌به‌بیت را می‌شکند.
- ❌ دست‌زدن به `contracts.ts` بدونِ ساختِ نسخه‌ی v2 + adapter.
- ❌ ساختِ اندیکاتورِ تکراری که مفهومش قبلاً در بانک هست.
- ❌ اعدادِ رند برای دوره‌ها.
- ❌ Batch کردنِ چند تغییر در یک commit — هر فایل، یک commit+push.

> **یک‌جمله‌ای:** «یک اندیکاتورِ مفهومیِ تازه، بدونِ look-ahead، با `active:false`، تست‌شده برای برابریِ
> بیت‌به‌بیت، مستندشده در `docs/indicators/`، و checkpoint‌شده بعد از هر فایل — این تمامِ وظیفه‌ی توست.»
